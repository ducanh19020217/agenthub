# Báo Cáo Khảo Sát & Đánh Giá Frontend Web Dashboard (`web/src`)

**Thời gian thực hiện**: 06/11/2026  
**Phạm vi khảo sát**: Toàn bộ codebase frontend `web/src` (~156 file TS/TSX)  
**Mục tiêu**: Phát hiện các vấn đề chức năng (functional bugs), trải nghiệm người dùng (UX), khả năng tiếp cận (Accessibility - a11y), quản lý state, memory leak, rủi ro bảo mật (XSS/URL redirection) và hiệu năng.

---

## 1. Tóm Tắt Tổng Quan

Frontend AgentHub được xây dựng trên nền tảng React 18, Vite, TypeScript, Tailwind CSS, TanStack React Query và xterm.js. Ứng dụng có độ phủ kiểm thử khá tốt (67 file test, 568 tests pass), hỗ trợ song ngữ `vi`/`en` và giao diện dark/light theme.

Tuy nhiên, qua quá trình rà soát chuyên sâu từng module theo yêu cầu, chúng tôi đã phát hiện **40 vấn đề** cụ thể cần được cải tiến, chia theo 3 mức độ:
- **Ưu tiên Cao (High - 14 vấn đề)**: Các lỗi tráo dữ liệu cột (data mismatch), rò rỉ bộ nhớ (memory leaks), mất state biểu mẫu (form state wipeout), thiếu bẫy bàn phím trên modal lớn, sập phân trang khi có SSE, và rủi ro link độc hại / IME nhập liệu.
- **Ưu tiên Trung bình (Medium - 20 vấn đề)**: Polling dư thừa, thiếu loading/error state, lỗi hiển thị sự kiện, nuốt lỗi promise, thiếu `remarkGfm` cho markdown, và vi phạm cấu trúc accessibility ARIA.
- **Ưu tiên Thấp (Low - 6 vấn đề)**: Hardcode số liệu hiển thị, dead code / tautology CSS token, thiếu timer phụ cho đồng hồ đếm ngược.

## 3. Kiến Trúc State Management & Đề Xuất Cải Tiến Cốt Lõi

Qua phân tích cấu trúc, chúng tôi nhận thấy các nguyên nhân gốc rễ (root causes) dẫn đến các vấn đề trên bao gồm:

### 3.1. Sự chồng chéo giữa React Query Cache và `useState` cục bộ
- Nhiều trang (`TaskDetailPage`, `SettingsPage`, `TasksPage`, `OpenProjectSettings`) sao chép dữ liệu từ React Query sang mảng hoặc object `useState` cục bộ bằng `useEffect(() => setState(data), [data])`.
- Điều này dẫn đến hiện tượng **Duplicate State** và **Race Condition**: Khi SSE kích hoạt `invalidateQueries`, dữ liệu từ server kéo về sẽ ghi đè và làm mất sạch các chỉnh sửa chưa lưu của người dùng (như trên `SettingsPage`), hoặc làm sập danh sách phân trang (như trên `TasksPage` Kanban).
- **Khuyến nghị**:
  1. Với dữ liệu dạng danh sách phân trang / infinite scroll: dùng `useInfiniteQuery`.
  2. Với biểu mẫu cấu hình: chỉ dùng `useState` cho form draft và có cờ `isDirty` bảo vệ, không để `useEffect` tự động reset form khi server refetch.

### 3.2. Vòng đời SSE và Module-Scope Cache
- `connectSSE` hiện đang gắn vào `AppShell` phụ thuộc vào `config`. Việc này gây vòng lặp ngắt/kết nối lại mỗi khi cấu hình được lưu.
- Bộ nhớ đệm log ở module scope (`runLogs` trong `sse.ts`) hoạt động như một singleton không giới hạn, rất nguy hiểm cho các ứng dụng chạy dài ngày trên trình duyệt.
- **Khuyến nghị**: Quản lý vòng đời EventSource độc lập với các query khác, dùng store có dọn dẹp (như TanStack Query cache với `gcTime` và `maxPages`).

### 3.3. Quy chuẩn Accessibility (a11y) cho Drawer và Modal
- Component `Modal.tsx` đã được triển khai rất tốt với `useFocusTrap` và ARIA dialog semantics. Tuy nhiên, các panel lớn như `ProjectSettingsDrawer.tsx` và `ChatPage` mobile drawer lại tự viết container `fixed inset-0` mà không tái sử dụng `useFocusTrap`.
- **Khuyến nghị**: Chuẩn hóa toàn bộ Drawer và Slide-over panel qua component `Drawer` dùng chung có tích hợp sẵn `useFocusTrap`, bắt phím Escape và hỗ trợ đầy đủ ARIA attributes.
